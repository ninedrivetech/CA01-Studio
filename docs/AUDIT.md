# 代码审计与发布验证

日期：2026-10-26（Asia/Shanghai）。起始版本：`19afd32`。本次覆盖 React/TypeScript 界面、编码与分段、设备状态机、Rust IPC/串口、日志文件写入、安装器配置、便携打包与 GitHub Actions 发布。主线程阅读项目协议和使用指南；两轮只读独立复核分别检查前端/原生边界及变更后的会话/发布流程。

## 已修复

| 问题 | 处理与证据 |
| --- | --- |
| 后台串口任务在重连后可能操作新设备 | `serial_session.rs` 将每个任务绑定 `Arc<Session>`，断开先取消，再等待端口释放；Unix 伪终端回归验证旧任务不能发送到替代连接 |
| 版本采集移出全局槽位后，断开无法取消 | 采集保留会话并检查取消状态；伪终端回归在写入前阻塞工作线程，取消后断言没有版本命令 |
| 并发版本采集可能重复发命令 | 原子占用采集标志，重复请求不能取消第一个请求；独立回归覆盖 |
| 写入或恢复串口超时失败后继续使用不确定会话 | 原生失败关闭端口；前端写入失败同步断开，重连不重放旧队列 |
| 导入期间覆盖用户的新编辑 | 读取前后核对草稿，冲突保留当前内容并提示；浏览器回归用延迟文件读取验证 |
| 参数读回覆盖请求期间的新编辑 | 请求期间禁用声音参数和延时输入，完成后恢复编辑 |
| 串口搜索焦点缺少完整 combobox 语义 | 搜索输入补充角色、展开状态、自动完成与活动候选关系，键盘和焦点测试覆盖 |
| 非 Windows 首次启动默认显示 COM9 | 无保存端口时选取本机枚举结果；没有端口时允许手动指定 `/dev/...` |
| 日志文件名通过字符限制却超过 Linux 文件系统字节限制 | 前后端同时限制 80 字符、240 UTF-8 字节，为扩展名和重名后缀留空间 |
| WSL 未配置 XDG 下载目录时导出失败 | Linux 回退到本机 `~/Downloads`，保留界面显示实际路径的行为 |
| 原生深色下拉菜单与主题不一致、禁用按钮仍有 hover 高亮 | 使用主题对应的 `color-scheme`，禁用和按下状态分别反馈；连接状态增加边框与底色 |
| 报文预览只能用鼠标滚动 | 预览加入键盘焦点及可访问名称 |
| 构建依赖漏洞 | Vite 更新至 6.4.5，Vitest 至 4.1.12，修复 source-map-js；`npm audit` 为 0 |
| Rust 撤回版本和 Tokio 健全性告警 | serialport 4.10.0 → 4.10.1，Tokio 1.53.1 → 1.54.1 |
| 安装器未启用、缺少 Linux/macOS 和云端发布 | 启用 NSIS、deb/AppImage、app/DMG，统一便携打包并附文档与许可证 |
| 旧二进制可能被标为当前源码、来源记录未校验、标签移动 | 成功构建记录源码及输入哈希；正式打包要求干净且匹配的提交；来源 JSON 纳入校验和；CI 固定提交并在发布前复查标签 |
| 发布校验未要求三端完整 | 发布门禁检查 Windows/Linux/macOS 必需产物、版本、提交及来源；8 项测试覆盖损坏、缺文件、错误来源与脏工作树 |
| Windows 与 WSL 并行测试可能复用同一 localhost 服务 | 为测试分别使用 1431/1432 端口，关闭已有服务复用，并保留失败 trace |

## 验证方式

- 前端：31 项 Vitest 单测，8 项 Node 发布门禁测试，18 项 Playwright 交互测试（Windows Edge 与 WSL Chromium）；类型检查和 Vite 生产构建。
- Rust：Windows 测试与 fmt/Clippy，WSL 测试额外覆盖三个真实 Unix 伪终端回归；使用锁文件构建。
- 界面：检查四主题、中英文、375px 小屏、900px 最小桌面宽度及短窗口，覆盖模态焦点、减少动态效果、日志导出与分段预览；测试截图保存在 `test-results/`。
- 原生：Windows release exe 和 NSIS 安装后程序通过 WebView2 自动化；Linux 通过 tauri-driver/WebKitGTK 启动实际打包程序，检查离线载入、串口枚举、拒绝非法 IPC、模拟播报、UTF-8 文件保存和英文设置。
- 发布：`actionlint` 检查工作流，正式构建后执行 `verify-release.mjs`；云端只有三端测试、构建、原生检查及校验门禁均通过才发布。远端运行结果以 GitHub Actions 和 Release 记录为准。

仓库没有声明 `.clean/architecture.md` 分层规则，因此边界脚本不能提供自动分层结论；已人工检查 UI → 设备/协议 → IPC → 串口会话的依赖方向。结构扫描未发现模块循环；组件位置及 i18n 共置等提示符合仓库既有组织方式，本次未为套用目录模板迁移文件。

## 保留事项与边界

`cargo audit` 报告 0 项 vulnerability 类记录，但仍有 GTK3 生态的上游告警：`glib 0.18.5` 的 `RUSTSEC-2024-0429`（`VariantStrIter` 健全性问题），以及 `proc-macro-error`、五个 `unic-*` 包的停止维护记录。它们通过 Tauri/GTK3 传递引入，本项目没有直接使用 `VariantStrIter`。当前依赖链没有可直接替换的兼容修复，未屏蔽告警或宣称全部 Rust 风险已经消除；后续跟随 Tauri 的 GTK 依赖迁移处理。

真实模块、扬声器、跨平台 USB 驱动及实际语音效果不在模拟器/自动化的证明范围内。Windows 当前枚举到的是蓝牙串口；没有据此声称完成真实语音模块测试。macOS 在 Actions 中执行 Rust、浏览器测试和构建，未配置 Apple 开发者证书、签名公证或原生 UI 驱动。

本次没有改写持久化草稿或设备协议格式。回退可 revert 本次提交并重新构建旧标签；发布校验失败时不上传未验证产物，保留之前已发布文件。

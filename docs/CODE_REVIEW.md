## 仍建议处理的代码问题

以下是审查发现及后续建议，不表示本轮已全部修复。

1. **P2：分段间隙仍缺少统一的操作调度。** `Device.receive` 收到 4F 后先设置“空闲”，`nextSegment` 等待 40ms 才发下一段；这期间界面会重新开放部分操作。若状态查询占用 pending，下一段 request 会报“上一条命令尚未完成”，catch 清空后续队列。`Dashboard.run` 只保护用户触发操作，不能覆盖后台续段。建议将播放阶段和命令通道建模为明确状态，并集中调度续段、暂停、状态查询。依据静态控制流发现，本轮未加入这一时序的自动复现。
2. **P2：UTF-8 导入会静默替换坏字节。** `Dashboard` 使用 `File.text()`，GBK 文件误选或损坏 UTF-8 会转换为替代字符后覆盖草稿。建议使用 `TextDecoder('utf-8', { fatal: true })` 解码 ArrayBuffer，失败时保留原草稿并解释应使用 UTF-8。
3. **P2：实机测试恢复失败可能仍以成功退出。** `scripts/com9-hardware-test.ps1` 的恢复失败仅写检查记录或警告；`com9-capacity-test.ps1` 的 restored=false 也不会显式失败。自动化调用方只看退出码时可能误判。建议将恢复失败纳入最终退出状态，并记录原始测试失败与恢复失败两种原因。
4. **P2：长文本编辑仍会同步阻塞主线程。** memoize 避免无关刷新重复编码，但文本每次改变仍同步遍历全部内容；导入允许 1 MB，草稿也每次编辑同步写 localStorage。建议先用接近上限的中英文文本测量输入延迟，再考虑后台编码与草稿防抖，发送前必须校验结果对应当前文本。
5. **P3：空预览和筛选空状态表达不准确。** 无有效帧时仍显示“第 1 / 0 段”；日志已有数据但筛选无匹配时仍显示“连接设备后…”；建议分别显示“无可发送报文”和“无匹配记录”，后者提供清除筛选。
6. **P3：前端维护边界偏集中。** Dashboard 同时负责存储、文件导入、日志导出、设备操作和四个区域渲染；CSS 保留 `.device-panel` / `.device-body` 等旧布局规则。建议按连接、编辑器、参数、日志区逐步拆分，并在删除旧样式前核对设置弹窗共享选择器。

收到 41 后长期收不到 4F 时，目前会持续等待；这是避免未经确认自动续发的保守行为。后续可增加等待时长和“停止/重新连接”引导，不应直接套用 15 秒命令超时强制中止长语音。

## 界面优化与美化建议

已检查本轮浏览器截图中的浅色/深色首页、手机首页和深色设置，并通过流程测试覆盖四种主题、语言切换、弹窗键盘循环、375px 竖屏与横屏设置布局。

| 优先级 | 区域 | 建议与理由 |
| --- | --- | --- |
| 高 | 手机首页 | 设置已使用 44px 控件，但首页提示音、标记、日志工具仍多为 25–35px；使用小屏专属 44px 点击区域，允许内容纵向增长 |
| 高 | 字号 | 卡片脚注、HEX 和辅助说明多为 9–11px；桌面常用说明提升至 12px，日志/HEX 提供字号或展开模式；保持编辑区为视觉重心 |
| 中 | 播放反馈 | 将纯文字“完成 x/y 段”加上进度条，明确区分播报、暂停、等待回传和完成；状态需同时有文字，不能只靠颜色 |
| 中 | 语音参数 | 提升“未保存修改”的辨识度，保存后使用短暂成功提示；高级读法可折叠，优先呈现发音人、音量、语速、语调 |
| 中 | 通信记录 | 默认首屏只展示少量行，增加展开/收起日志区；冻结按钮选中时增加主题色背景，筛选结果为空时提供清除入口 |
| 中 | 发送预览 | 长文本允许上一段/下一段切换，并显示该段字节数；当前只显示第一段，不便排查后续文本 |
| 低 | 视觉统一 | 保留暖白/自然绿/深青/金色四主题，统一卡片圆角和间距；避免为设备工具添加大面积渐变、装饰动画或在线字体依赖 |

设计技能的搜索结果包含不适合本项目的应用商店落地页模式，未照搬；采用其可访问性、焦点、文本层级和减少动态效果检查项。没有声称已完成全页面 WCAG 对比度测量或真实屏幕阅读器验收。

## 后续优化实施（2026-09-21）

按用户后续指示完成以下修改；本节更新前文待办的实施状态。

- **续段调度**：命令请求串行执行，续段等待占用中的请求完成，分段间隙保持播放状态。停止、断开和暂停会使旧的续段任务失效；只有合成命令的 41 才标记当前分段已接收。补测了查询与续段竞争、分段间暂停/继续、断开重连，以及播放完成早于暂停确认的时序。
- **文本处理**：严格 UTF-8 解码，坏字节或超限文件导入失败时保留原草稿；编码移至 Worker，快速输入合并请求，只采用匹配当前文本和编码的结果。准备中禁用发送并显示状态。草稿采用300ms防抖，页面关闭或离开时保存最新值。
- **结构与加载**：拆出轻量 `protocolCore.ts`、`FramePreview`、文件导入函数和编码 hook。主页面 JS 由约452 kB降至约303 kB，编码 Worker约156 kB；这是解析与执行负担的分离，不意味着总下载体积按同样比例减少。
- **冷启动开发环境**：显式预构建Worker使用的编码依赖，避免清空Vite缓存后首次加载触发自动刷新并重置设备会话；冷缓存全量13项浏览器测试通过。
- **实机脚本**：原测试异常与恢复异常分别记录，恢复失败会导致失败退出；只做语法验证，未连接模块执行这些写参数脚本。
- **交互与视觉**：加入分段完成进度、逐段报文预览及字节数、日志展开、筛选空状态恢复；未保存参数和日志冻结状态加强显示，成功提示5秒后消失。手机首页控件至少44px高，日志筛选与工具分行，控制标记与提示音增加间距。
